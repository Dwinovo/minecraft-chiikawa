# 0.1.1 设计：口癖、互动与模型统一

> 基于 1.21.1 分支当前代码（提交 592a0554，已合入 faces 分支的四只新模型）。
> 原作依据见 [chiikawa-ip-research.md](chiikawa-ip-research.md)。

---

## 1. 目标与范围

**目标：** 让宠物更像原作里的它们——会说自己的口癖、会有表情、彼此之间有来往；八个角色的模型和武器统一到新风格。

**本版要做**

1. 口癖：宠物在对应时刻头顶冒出对话气泡，说原作口癖，同时张嘴。
2. 表情：八个角色有同一套表情动画（开心、哭、困惑、说话），现有的表情反应真正播出来。
3. 角色互动：几组原作里的来往，两只宠物一起演。
4. 古本屋和乌萨奇按新风格重做。
5. 原作武器建模：吉伊和小八的さすまた、乌萨奇的討伐棒，新增獭师父的剑。

**不在范围内**

- 讨伐排行、草むしり検定、報酬袋、原作食物、擬態型与キメラ、労働の鎧さん、Boss。
- 披风和尾巴的物理摆动（已取消）。
- 语音：口癖只出文字气泡，不加新的音频。

## 2. 现状

- **气泡：** 只有打工手册里有对话气泡（`ManualScene`，界面里画）。游戏世界里只有准星指着自家宠物时的头顶状态标签（`WorldSurface`）；本版删掉它，见 3.1。
- **张嘴：** 八个角色都有 `open_mouth1`、`open_mouth2` 动画，渲染器也会在它们播放时显示 `Mouth3`，但游戏里没有任何地方触发它们。
- **表情反应：** `PetReaction` 有开心、受伤、困惑、复活四种，服务端在拿到工钱、受伤、被喂食等时刻触发。它们要找的动画（`happy`、`hurt`、`confused`、`revive`）八个角色基本都没有，只有乌萨奇、小八、古本屋有 `scratch_head`，所以这些反应大多是静默的。
- **说话显示 `Mouth3`：** 吉伊、飞鼠、栗子馒头、獭师父、狮萨平时闭着嘴，渲染器只在张嘴动画播放时显示 `Mouth3`。乌萨奇的渲染器让 `Mouth3` 一直藏着，小八只在弹吉他时显示它，所以它们平时也是闭着嘴。
- **武器：** 三把"讨伐棒"是 Java 方块模型格式的一根细棍，吉伊、小八、乌萨奇各一把，都是石剑档的剑，在剑士工具标签里。獭师父没有武器。
- **古本屋：** 7 月加入时的模型，用的是小八的骨架和动画，之后只加过包的挂点；渲染器让 `Mouth3` 一直藏着，所以平时是闭嘴的 ω。

## 3. 口癖

### 3.1 玩家看到的

- 宠物在特定时刻头顶冒出一个对话气泡，写着它的口癖，同时播放张嘴动画。气泡停留约 3 秒后淡出。
- 附近的玩家都看得见（16 格内），和宠物是谁的无关；F1 隐藏界面时一起隐藏。
- 气泡的高度固定：原版名牌位置再往上一行，名牌显不显示都一样，出现后不会跳。
- 头顶状态标签删掉：它和气泡同时出现时互相顶来顶去，而宠物在做什么、做到哪了，右键面板里本来就实时显示。车万女仆也是头顶只有气泡，状态在界面和 Jade、The One Probe 里。
- 同一只宠物说完一句后有冷却，不会连续刷屏；附近宠物很多时，同一时刻最多几只在说话。

### 3.2 什么时候说

| 时刻 | 已有的触发点 |
| --- | --- |
| 被驯服 | 驯服成功 |
| 受伤 | 受到伤害（和"哭"表情一起） |
| 开始讨伐 | 进入战斗意图 |
| 拿到工钱 | 工作牌完成到账 |
| 买到东西、当场吃掉 | 商店购物 |
| 送礼 | 把礼物交给主人 |
| 复活 | 玩偶放上蛋糕 |
| 闲着 | 闲逛时低概率随机 |
| 互动 | 见第 5 节 |

### 3.3 说什么（初稿，按原作）

| 角色 | 口癖示例 |
| --- | --- |
| 吉伊 | 「ヤダッ!!」「ンショ…」「ワァ…」、讨伐时「ヤーッ!!!」、受伤时哭 |
| 小八 | 「なんとかなれーッ!!」「ってコト!?」「泣いちゃった!!」 |
| 乌萨奇 | 「ウラ」「ヤハ」「プルルル」「ハァ？」 |
| 狮萨 | 礼貌的招呼，冲绳梗（さんぴん茶） |
| 飞鼠 | 「褒めろ」「慰めろ」「ついにやったゾ!!」 |
| 栗子馒头 | 吃喝后「ハーッ…」 |
| 獭师父 | 简短的前辈口吻 |
| 古本屋 | カニ挨拶 |

口癖按各语言翻译：日文用原作台词，中文和英文各自译成当地粉丝熟悉的说法。

### 3.4 数据

每个角色说什么、在什么时刻说、概率和冷却，都放在数据包里，由数据生成写出默认值，两个加载器读同一份：

`data/<命名空间>/pet_voice/<角色>.json`

```json
{
  "lines": {
    "hurt":   [{ "text": "voice.chiikawa.chiikawa.hurt.1", "weight": 1 }],
    "hunt":   [{ "text": "voice.chiikawa.chiikawa.hunt.1", "weight": 1 }],
    "idle":   [{ "text": "voice.chiikawa.chiikawa.idle.1", "weight": 2 }]
  },
  "chance": { "idle": 0.001 },
  "cooldown_ticks": 200,
  "crowd_limit": 3,
  "talk_ticks": 60,
  "hearing_range": 16.0
}
```

- `text` 是翻译键，文字写在语言数据里。
- 没写某个时刻，这个角色那时就不说话。
- `chance` 没写的时刻都是 1；闲着（`idle`）是每 tick 的概率，和原版环境音一样按 tick 掷。
- `crowd_limit`：听得见的范围内已经有这么多只在说话时，这只就先不说。
- `talk_ticks`：气泡停留多久；`hearing_range`：多远的玩家听得见，默认 16 格，和原版满音量声音的传播距离一样。气泡时长随同步包发给客户端，所以专用服务器上客户端也用数据包里的值。

### 3.5 同步

- 服务端决定说哪一句，保证所有玩家看到的一样。
- 通过一个服务端到客户端的包（宠物实体 id + 翻译键）发给追踪这只宠物的玩家，客户端收到后开始显示气泡，并播放 `open_mouth1` 或 `open_mouth2`（按台词固定选一个，大家看到的一样）。张嘴放在反应层之上单独的 `talk` 层：同一时刻触发的表情（开心、哭）晚一步到客户端，放在同一层会把张嘴顶掉；`talk` 层只动嘴，表情的其余部分照常。
- 气泡由 `SpeechBubbleRenderer` 在世界里画（`WorldSurface`），宠物渲染器把它组合进来；样式和打工手册里的气泡是同一个 `Bubble` 组件。

## 4. 表情

### 4.1 同一套动画名，各自的表情

八个角色都有下面这些动画名，但脸上做什么按各自在原作里的性格来，不是一套表情套给所有人：

| 动画 | 用在 |
| --- | --- |
| `blink` | 一直循环，眨眼（已有） |
| `open_mouth1`、`open_mouth2` | 说话，张嘴，显示 `Mouth3`（已有） |
| `happy` | 开心：被驯服、喂食、拿到工钱、买到东西、送礼、接到工作牌 |
| `hurt` | 受伤 |
| `confused` | 困惑：驯服没成功 |
| `revive` | 复活 |

| 角色 | 开心 | 受伤 | 困惑 | 复活 |
| --- | --- | --- | --- | --- |
| 吉伊 | 眼睛弯成 ^ ^、脸红、小跳 | 哭：眼泪、波浪嘴 | 冒汗、缩一下 | 又哭又笑 |
| 小八 | 张嘴大笑、蹦一下 | 不哭：皱眉咬牙，张嘴喊 | 歪头 | 感动得哭出来 |
| 乌萨奇 | 张嘴、跳得很高 | 不哭：瞪眼、跺脚 | 挠头（已有 `scratch_head`） | 照常开心，当没事发生 |
| 飞鼠 | 得意叉腰 | 大哭（假哭） | 不满、鼓腮 | 装可爱 |
| 栗子馒头 | 闭眼吐气、脸红 | 皱眉忍住，不哭 | 沉默，冒一个"…" | 闭眼吐气 |
| 獭师父 | 轻轻点头 | 咬牙、眉毛压低，不哭 | 抱臂想一想 | 点头 |
| 狮萨 | 笑眯眼、脸红 | 不哭：慌张冒汗 | 慌张冒汗 | 开心得哭出来 |
| 古本屋 | 举起蟹钳（カニ挨拶） | 缩一下，一颗小眼泪 | 歪头 | カニ挨拶 |

- 依据：吉伊"受惊或遇到讨厌的事就会哭"（官方）；乌萨奇原作里不哭；小八、狮萨哭过，但一般不哭，只在被感动时；飞鼠爱假哭；栗子馒头、獭师父成熟寡言、表情坚毅（研究笔记第 2 节）。
- 表情需要的新零件（眼泪、弯眼、汗）做成脸上的骨骼，平时隐藏，由动画控制显示。
- `FaceAnimationsTest` 改为检查八个角色都有这些动画名。

### 4.2 渲染器

- 八个角色统一成"说话时才显示 `Mouth3`"，规则留在各自的渲染器里：乌萨奇从一直藏着改成说话时显示，小八改成弹吉他或说话时显示。

### 4.3 怎么做的

- **表情零件是模型里的骨骼：** 开心眼 `HappyEyes`、哭眼 `CryEyes`、眼泪 `Tears`（古本屋是一颗 `Tear`）、汗 `Sweat`、栗子馒头头顶的"…" `Dots`。基岩版模型的骨骼没法默认隐藏，所以由渲染器的显示规则带出来：`ShownDuring.any("hurt", "revive")` 表示只在这些动画播放时显示。哪只宠物有哪些零件、在哪个表情里出现，写在它自己的渲染器里，因为每张脸都不一样。
- **被替换的部分由动画藏起来：** 表情动画把原来的眼睛（`Eyes` 或 `Eyelid`）缩放到 0。狮萨和小八只藏眼睛、留着眉毛，因为狮萨的眉毛是它的特征。
- **不需要零件的表情只靠动画：** 獭师父点头、压眉；乌萨奇眉毛稍微压低、跺脚（它的"ハァ？"全在声音里，脸几乎不变）；小八受伤时皱眉、张嘴。
- **没有的表情按 `PetReaction` 退回：** 复活没有专门动画的退回开心；困惑先找 `scratch_head`（小八还有），再找 `confused`。重做过的乌萨奇和古本屋没有 `scratch_head` 了，所以补了 `confused`。
- `FaceAnimationsTest` 检查八个角色都有开心、受伤、困惑，以及表情动画只动模型里有的骨骼。

## 5. 角色互动

### 5.1 玩家看到的

两只宠物离得近时，偶尔会按原作的关系一起演一小段：一只走向另一只，两只面对面，各自播动画、冒气泡，演完各走各的。

### 5.2 初版几组（按原作）

| 互动 | 发起 | 对象 | 过程 |
| --- | --- | --- | --- |
| 缠人 | 飞鼠 | 吉伊优先，其次任何人 | 飞鼠凑上去扒住头，说「褒めろ」；对方哭脸，说「ヤダッ!!」。没人夸它，松手时假哭，说「慰めろ」 |
| 请客 | 獭师父 | 吉伊、小八 | 獭师父从背包里拿一份吃的递过去，对方当场吃掉、开心 |
| 送咖啡 | 栗子馒头 | 刚完成除草牌的宠物 | 走过去递一杯，对方开心，短时间更有干劲 |
| カニ挨拶 | 古本屋 | 飞鼠、吉伊、小八 | 两只面对面做カニ挨拶 |
| 听演奏 | 任何人 | 正在街头演奏的小八 | 走到旁边坐下听，偶尔鼓掌；獭师父、栗子馒头安静地听，不鼓掌 |

各方怎么反应按原作的性格来：缠人时吉伊哭，小八、乌萨奇、狮萨、古本屋困惑，獭师父、栗子馒头不动声色；缠人的结尾是飞鼠的假哭（它的 `hurt` 表情本来就是假哭）。

### 5.3 在 AI 里怎么做

- 任何两只宠物之间都可以互动：不论是不是同一个主人，野生的也算。
- 意图类别 `SOCIAL`，许可规则和闲逛一样：坐下时不做，其他状态和野生宠物都可以。跟随时只在离主人很近时发生，由跟随的锚点拴绳自然限制。
- **想到：**`PetSocialSensor` 每 2 秒看一眼原版传感器已经看见的宠物，按每段互动的 `chance` 想到一段，写进 `INTERACTION_PLAN` 记忆（只是个念头，下次张望就过期）。谁能和谁演由 `SocialRules` 判断：距离、对象的种类和优先级、这一对的冷却、对方在做什么、对方刚做完什么、发起方背包里有没有要递的东西。
- **发起：**`SocializeIntent`（0.35，高于闲逛、低于一切差事和工作）走过去演。出发时向闲着的对方写一条带过期的 `INTERACTION_RESERVATION`：对方的 `CooperateIntent`（0.5）接手，原地停下、转向来的宠物，别的宠物抢不走；预约到期或发起方走不过去就作罢。演奏中的小八不预约，照常弹，谁都可以来听。
- **演：**两只碰面那一刻，要递的东西从发起方背包里拿出来、当场吃掉；然后两边各自开始自己那一份（`PartPlayer`）：摆好姿势（同步的 `PERFORMANCE`，动画层照 `ACTIVITY` 那样读），打开场的「节拍」，演的过程中到点打「时不时」的节拍，结束时打收尾的节拍、放下姿势。发起方和对方用的是同一个 `PartPlayer`，由各自的行为（`SocializeBehavior` / `CooperateBehavior`）组合进来。
- **节拍（`Beat`）**是一样东西写三处：一个只做一次的动作（按名字）、一个表情（`PetReaction`）、一句话（`VoiceMoment`，按这只宠物自己的 `pet_voice` 台词说），都可以不写。表情和话走现有的反应触发和说话；按名字的动作由 `PetGesture` 发一个 `PetGesturePayload`（实体 id + 动画名）给看得见这只宠物的玩家（宠物的追踪范围内，发法和 `PetSpeech` 一样是原版发声音那套），客户端在动作层上播放；模型里没有这个动画就什么都不播，不报错。动作放在动作层而不是反应层：同一拍里的表情走反应层，两者不会互相顶掉。
- **冷却**按「这一对宠物」和「这一种互动」记（`SOCIAL_COOLDOWNS`），两只都记，同一对不会反复演同一段，和别的宠物照样可以。不管演完、走不过去还是被叫走，都记。
- **说话的冷却照常算。**节拍里的话和别的时候一样受这只宠物的 `cooldown_ticks`、人群上限约束：鼓掌时的那句，冷却没过就只鼓掌不说话。缠人这段开场说「褒めろ」、80 tick 后收尾说「慰めろ」，所以飞鼠的冷却定成和气泡时长一样（60 tick）——它从不消停，只在上一句还挂在头上时闭嘴。

### 5.4 数据

`data/<命名空间>/pet_interaction/<id>.json`，默认五段由数据生成（`PetInteractionData`）写出，整合包可以增删、覆盖。以「听演奏」为例：

```json
{
  "initiators": [
    {
      "pets": ["chiikawa:chiikawa", "chiikawa:hachiware", "chiikawa:usagi",
               "chiikawa:shisa", "chiikawa:momonga", "chiikawa:furuhonya"],
      "pose": "sit",
      "begin": { "reaction": "happy", "voice": "listen" },
      "now_and_then": {
        "every_ticks": { "type": "minecraft:uniform", "min_inclusive": 60, "max_inclusive": 160 },
        "animation": "clap",
        "voice": "listen"
      }
    },
    { "pets": ["chiikawa:rakko", "chiikawa:kurimanju"], "pose": "sit", "begin": { "voice": "listen" } }
  ],
  "partners": [ { "pets": ["chiikawa:hachiware"] } ],
  "partner_state": "playing_music",
  "notice_distance": 12.0,
  "approach_distance": 3,
  "reservation_ticks": 400,
  "duration_ticks": 400,
  "cooldown_ticks": 6000,
  "chance": 0.6
}
```

| 字段 | 意思 |
| --- | --- |
| `initiators` / `partners` | 发起方和对象的各个「角色」。每个角色用 `pets` 列实体 id 或 `#标签`；一只宠物演第一个点到它的角色，所以同一段里每个角色可以有自己的反应。对象按列出的先后算优先：先找最靠前那一类里最近的一只 |
| `pose` | 整段都保持的动画（坐下、扒住……），没有这个动画就照常站着 |
| `begin` / `end` | 碰面那一刻、结束那一刻的节拍：`animation`（只做一次的动作）、`reaction`（`happy` / `hurt` / `confused` / `revive`）、`voice`（`pet_voice` 里的时刻名），都可以省 |
| `now_and_then` | 演的过程中反复打的节拍，字段同上，外加 `every_ticks`：每次隔多久，原版的整数分布（写一个数就是固定间隔，写 `uniform` 就是每次重抽），至少 1 |
| `partner_state` | 对方要在做什么：`idle`（闲逛，默认；会被预约、停下来配合）或 `playing_music`（正在演奏；不预约，照常弹） |
| `partner_finished` | 可选：对方要刚做完哪种牌，`{ "slip": 牌型 id, "within_ticks": 多久以内 }` |
| `hands_over` | 可选：发起方从背包里拿出来递过去的东西（物品 id 或 `#标签`），对方当场吃掉；背包里没有就不发起 |
| `partner_eager_ticks` | 对方之后多久干活更起劲，和吃了简单料理一样，默认 0 |
| `notice_distance` | 多远以内会想到对方（宠物只看得见 16 格内的） |
| `approach_distance` | 走到多近开始演 |
| `reservation_ticks` | 走过去最多花多久，对方也只等这么久 |
| `duration_ticks` | 演多久 |
| `cooldown_ticks` | 同一对多久不重演这一段 |
| `chance` | 每次张望（2 秒一次）想到这一段的概率 |

默认五段：

| 互动 | 发起方 | 对象（按优先级） | 演多久 / 冷却 / 概率 |
| --- | --- | --- | --- |

## 8. 闲着时的习惯

### 8.1 玩家看到的

宠物闲逛或坐着时，每隔一会儿挑一件事做：看身边的玩家、看附近的动物或别的宠物、走几步、或者就待着。挑哪件、看多远的人、看多久，每个角色不一样，按原作的性格来：

| 角色 | 看玩家 | 看动物、别的宠物 | 走几步 | 待着 | 依据 |
| --- | --- | --- | --- | --- | --- |
| 吉伊 | 常看（3），6 格内，1–2 秒 | 2，5 格内，1–2 秒 | 2 | 1，1.5–3 秒 | 胆小又黏人：常偷偷瞄一眼，很快移开 |
| 小八 | 常看（3），8 格内，3–5 秒 | 3，8 格内，3–5 秒 | 2 | 1 | 开朗、好奇、爱拍照：谁都要好好看一眼 |
| 乌萨奇 | 很少（1），5 格内，不到 1.5 秒 | 1 | 最多（4） | 1，不到 1.5 秒 | 停不下来，一瞥就走 |
| 狮萨 | 常看（3），6 格内，2–4.5 秒 | 2 | 1 | 1 | 有礼貌、亲近人：有人来就转过去 |
| 飞鼠 | 最常看（5），10 格内，4–7 秒 | 1 | 2 | 1 | 一心想被人看：远远就盯着你，等你夸 |
| 栗子馒头 | 2 | 1 | 1 | 最多（4），4–8 秒 | 慢悠悠，一坐就是好久 |
| 獭师父 | 很少（1） | 常看（3），10 格内 | 2 | 1 | 讨伐第一，留意周围动静多过看人 |
| 古本屋 | 2，3–6 秒 | 1 | 1 | 多（3），4–8 秒 | 安静，抬头看人时看得久 |

括号里是权重；没写的项和原来一样（权重 2、5 格、约 2 秒；待着 1.5–3 秒）。附近没有人或动物可看时，就从别的事里挑。坐着时不走动，其余照常。

### 8.2 数据

在性格文件 `pet_personality/<宠物>.json` 里加一项 `idle`，每一项都可以不写：

```json
"idle": {
  "look_at_player":   { "weight": 5, "range": 10, "ticks": [80, 140] },
  "look_at_creature": { "weight": 1, "range": 5,  "ticks": [20, 40] },
  "stroll": 2,
  "rest": { "weight": 1, "ticks": [30, 60] }
}
```

- `weight` 为 0 就从不做这件事；`range` 最多 16 格（宠物看得见周围谁的范围）；`ticks` 是时长范围（也可写成 `{ "min_inclusive": 80, "max_inclusive": 140 }`），1 到 1200 tick。
- 时长用原版的 `InclusiveRange` 而不是 `IntProvider`：性格在游戏注册表就绪前就要能加载（单元测试就在这种情况下用它），`IntProvider` 一加载就要注册表。

### 8.3 怎么做的

- **按权重挑一件事**是一个组合行为 `WeightedChoice`：和原版 `RunOne` 一样按权重打乱、第一个能开始的就做，区别是权重每次挑的时候才从宠物的性格里取。原版 `RunOne` 的权重在大脑建好时就定死了，数据包重载后要等宠物重新加载才生效。
- **看人**是 `GlanceBehavior`：和原版 `SetEntityLookTarget` 一样从宠物看得见的实体里挑最近的，通过同一个 `LOOK_TARGET` 记忆让头转过去；看多久由习惯决定，而不是由核心层 `LookAtTargetSink` 的固定 45 tick 决定（那一层工作时看作物也用，所以不动它），人走出范围就不看了。
- **待着**是 `RestBehavior`，相当于时长可变的原版 `DoNothing`；**走几步**还是原来的 `RandomWalkTask`。
- 闲逛（`IDLE`）四件都有，坐着（`STAY`）没有走几步。GameTest `a_sitting_pet_looks_at_who_comes_by` 覆盖整条链路：坐着的飞鼠会转头看身边的玩家；把它看玩家的权重改成 0，这个用例就失败。
