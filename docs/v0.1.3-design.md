## 2. 小八的相机

### 2.1 原作与取舍

- **小八爱拍照是官方设定**：电影官网的角色介绍写着它爱用相机拍照。
- **动画第 78 到 81 集**（[ABEMA](https://times.abema.tv/articles/-/10145501)、[电击](https://dengekionline.com/articles/192936/)）：
  - 第 78 集「カメラ買っちゃった」：小八终于买下想要很久的相机，舍不得撕掉镜头上的保护膜。
  - 第 79 集「試し撮り」：试拍。
  - 第 80 集「どんどん撮ろう」：给吉伊和乌萨奇拍照，吉伊害羞，乌萨奇弯腰从两腿之间看镜头摆出「ヤハー!」。
  - 第 81 集：小八给大家看照片，擦相机时发现一道划痕，说「离远点看不出来，这也是味道嘛」。
- **第 95 集**：小八给吉伊看洗出来的照片，吉伊发现小八拍照时总吐舌头。**洗出来的照片是原作里有的。**
- **原作拍的都是伙伴**，没有找到拍风景的情节。风景是我们加的，权重放低，见 2.3 节。
- **相机自己买**：原作里是小八攒钱买的。商店卖相机，小八攒够钱会自己去买；主人也可以买来送它。
- **只有小八会拍**，和八音盒只有小八会弹一样。
- **和车万女仆不重叠**：车万女仆的相机是把女仆"收"进照片里搬运，不拍画面。我们的照片只是画面，不会把谁变成物品。
- **外观**：手办（ねんどろいど ハチワレ）带一个相机配件，是最好的官方立体参考。建模前先找配件的产品图，见 2.8 节。

### 2.2 规则

| 项 | 默认 | 说明 |
| --- | --- | --- |
| 谁会拍 | 小八 | 自己的小八，背包里同时有相机和胶卷。野生的和别人的不拍 |
| 相机放哪 | 背包任意格 | 不占主手，打工工具照用；拍的时候掏出来，拍完收起 |
| 胶卷 | 一卷拍 8 张 | 照片传回服务器、存好以后才记到胶卷上；没拍成不占一张。拍到一半的接着拍，拍满了换新的一卷 |
| 主人要在附近 | 64 格内、同一个维度 | 画面在主人的客户端上渲染，主人看不到的地方拍不了 |
| 多久拍一张 | 每张之间至少半个游戏日 | 加上"有没有好时机"，一天拍一两张 |
| 照片去哪 | 记在胶卷上 | 没拍满的胶卷留在小八背包里，主人随时可以拿来看；拍满的胶卷进送礼的池子，权重高，很快会递给主人，见第 3 节 |
| 获得相机 | 商店，32 绿宝石 | 小八会自己攒钱买：还没有相机时，它不买别的东西，把钱攒下来；不合成 |
| 获得胶卷 | 商店，2 绿宝石 1 卷 | 小八会自己买，**只在有相机、手上没有没拍满的胶卷时买** |
| 自己用的 | 相机、没拍满的胶卷 | 不进送礼的池子 |

**拍照的过程**：小八走到合适的位置，转向要拍的对象，举起相机（相机作为模型上的道具骨骼显示），停一下，"咔嚓"，然后收起相机。被拍的伙伴会摆姿势、说一句话，见 2.3 节。

### 2.3 拍什么

| 对象 | 权重 | 好时机 |
| --- | --- | --- |
| 主人 | 3 | 主人在身边、看得到 |
| 伙伴 | 5 | 附近在演小场面、在听演奏、刚看完考试结果；没有这些时，随便一只闲着的伙伴 |
| 风景 | 1 | 日出、日落；走到没拍过的群系 |

- 每次想拍时，按"现在有哪些好时机"和权重挑一个对象；什么时机都没有就不拍。
- **有时摆姿势，有时随手一拍**，各一半（数据可调）：
  - **摆姿势**：小八喊一句（新说话时刻 `photo`），被拍的伙伴转过来摆姿势、说一句（新说话时刻 `photographed`）。乌萨奇弯腰从两腿之间看镜头喊「ヤハー」，吉伊害羞；其他角色先看着镜头，以后再逐只加姿势。
  - **随手一拍**：小八不出声，被拍的伙伴照样做自己的事，不会停下来，拍下的是生活中的样子。
  - 拍主人和风景时，"摆姿势"只是小八喊不喊那一句。

### 2.4 胶卷就是相册

- **没有单张的照片物品**。照片记在胶卷上：胶卷物品上记着这一卷拍了哪几张，每张的照片编号、拍的是谁、第几天、谁拍的；画面本身存在世界里，见 2.5 节。
- **新胶卷**可以堆叠；拍过的胶卷一卷一个，不能堆叠。提示里写"已拍 3/8"。
- **右键胶卷**：打开像手册一样的纸框，一页一张，左右翻页；每张下面写"小八拍的 · 第 12 天 · 吉伊"。没拍过的新胶卷右键没有反应。
- **物品图标**：16×16 的平面贴图（现有的胶卷图标）。
- **画面大小**：320×240（数据可调），存成 PNG。

### 2.5 技术：真实画面怎么来

照 Exposure 模组的做法（它的相机架就是"非玩家的实体，在玩家的客户端上拍"），按我们的结构来：

1. **服务器决定拍**：小八举起相机，到"咔嚓"那一刻，服务器生成一个照片编号，记下"等这个编号的画面，来自这位主人，60 秒内有效"，然后通知主人的客户端：拍谁、小八的位置和朝向。
2. **主人的客户端在后台渲染一帧**：
   - 把相机实体临时换成小八，渲染到一块单独的画布上（`TextureTarget`），不显示在屏幕上，关掉界面、手和方块选框，然后换回来。主人的屏幕不受影响，不闪也不跳。
   - 视角固定用数据里的 `fov`，不受主人疾跑、药水这些视野变化影响。
   - 读出像素，缩到 320×240，压成 PNG。缩图和压缩放到后台线程。
   - **光影实测可用**（2026-10-10，NeoForge 1.21.1，Exposure 1.9.19 默认配置，Sodium 0.8.12 + Iris 1.8.14 + Complementary Unbound r5.8.1）：Exposure 用的就是这种后台渲染，手持相机拍和相机架从另一个位置、另一个朝向拍，照片都带着完整的光影效果。它的旧 issue（#212、#277）说开光影会拍出空白，在这套组合下没有出现。
   - 代价：拍的那一帧要把世界多画一遍，那一帧的耗时大约翻倍。所以挑时机：主人刚受伤、在战斗、在骑乘或飞行时不按快门，等主人闲下来再拍。
   - **还要验证**：别的光影包（Photon、Kappa 等）、Oculus（1.20.1 Forge）、Distant Horizons 同装。如果某种组合拍不出来，再考虑备选的"闪光帧"：临时把主人的镜头换到小八身上正常渲染一帧、读出主画面，用一下闪光盖住视角切换。
3. **分块上传**：客户端到服务器的单个包最多 32 KiB，按块传，服务器拼好。只收"正在等"的编号、来自那位主人、总大小不超过上限的数据，其余的丢掉。
4. **存进世界**：存成 `世界/data/chiikawa/photos/<编号>.png`，跟着存档走。然后扣胶卷、做照片物品、交给送礼流程。
5. **看照片**：客户端先看自己有没有缓存，没有就向服务器要，服务器分块发回来，做成贴图显示。缓存只在内存里，换世界清空。
6. **失败**：主人走远了、下线了、60 秒没传回来，就当没拍，不扣胶卷，小八过一会儿再找机会。

**主人看不到的地方拍不了**：渲染只能用主人客户端已经加载的区块，所以要求主人在 64 格内。这也正好：小八是拍给你看的。

### 2.6 数据

- **`data/<命名空间>/pet_camera/<物品>.json`**：按相机的物品 id 一个文件，照 `pet_whistle` 的写法：
  - 胶卷用哪个物品 `film`
  - 主人要多近 `owner_range`
  - 每张之间最少多久 `cooldown_ticks`
  - 画面大小 `width`、`height`，视角 `fov`
  - 三类对象的权重 `subjects`
  - 举相机多久 `aim_ticks`
- **商店**：相机和胶卷进 `shop_catalog/general.json`。
- **性格**：小八的 `likes` 加相机和胶卷。"有相机才买胶卷"这样的条件现在的 `likes` 写不出来，要给喜好加一个可选的"要先有某件东西"（`requires`），见 2.7 节。
- **说话**：`pet_voice` 新加 `photo`、`photographed` 两个时刻。

### 2.7 代码

现有的、直接用的：

- **送礼**：照片交给 `setPendingGift`，现有的送礼意图和行为会把它递给主人。
- **从背包里用东西**：照种子、箭的写法，从背包里找相机、扣一卷胶卷（`SocialRules#takeHandOver` 是最接近的例子）。
- **道具骨骼**：`PropBone` 加 `CAMERA`，在 `photo` 动作期间显示；`HeldItemLayer` 在道具显示时自动收起手上的东西。
- **数据加载**：照 `WhistleSettings` + `WhistleSettingsLoader` + `WhistleSettingsData` + `WhistleSettingsProvider` 四件套。

要新做的：

- **拍照意图 `take_photo`**：通用意图，`canRun` 检查是小八、有相机和胶卷、主人在范围内、冷却已过、有好时机；新的意图类别要在 `PetConstraints` 里写明什么时候允许（坐下时不拍，跟随和自由活动时拍）。
- **挑对象**：纯函数，输入"现在有哪些好时机"和权重，输出拍谁，方便单元测试。
- **喜好的条件**：`Personality.WeightedItem` 加可选的 `requires`；`ShopBasket` 挑东西时跳过条件不满足的。
- **照片存储**：服务器端的照片库（存取 PNG、等待中的编号、过期清理）。
- **网络**：服务器到客户端的"拍这一张"、客户端到服务器的分块上传、按编号要照片、服务器到客户端的分块回传。两个加载器各注册一遍。
- **客户端渲染**：后台渲染拍照、照片贴图缓存、看照片的界面。**这是这一版里各版本差别最大的一块**：1.21.5 起原版的渲染底层大改过，1.20.x、1.21.4 及以前、1.21.5 及以后、26.x 很可能各要一套写法。

### 2.8 模型和动作

- **相机**：立体的，在 Blockbench 里做成 Bedrock 模型，一个纹素对一个像素。先找手办相机配件的图，照着做，做好给你看。
- **小八身上的相机骨骼**：加在小八的模型里，和吉他、考试铅笔一样。
- **动作**：小八的举相机、按快门；每个角色"被拍"的姿势。在 Blockbench 里逐只做，对着原作确认，从几个角度截图给你看。
- **照片和胶卷的图标**：16×16 贴图。

### 2.9 测试

- **单元测试**：挑对象、喜好的条件、数据解析、上传拼块和校验（编号不对、超大小、超时）。
- **GameTest**：有相机有胶卷才拍；没胶卷不拍；坐下不拍；拍成后扣一卷、照片进待送礼物；上传失败不扣胶卷；小八只在有相机时买胶卷。
- **手动**：真实画面要进游戏看，单人和联机各一次；光影在 Iris、Oculus 上各拿常用光影包拍过。

## 3. 送礼和买东西分开

### 3.1 现状和问题

0.1.0 起，礼物只从逛商店里来：宠物每买 3 次大约有 1 次被定成"给主人买的"，买到的东西放进单独的"待送礼物"格子，送出去之前不再买礼物。两件事绑在一起，宠物别的东西（比如小八的照片）没法送。

### 3.2 规则

- **买东西**：只给自己买喜欢的，买到的一律放进自己背包。不再有"这次是给主人买的"。
- **送礼物**：单独的一件事。自己的宠物隔一阵（最少一个游戏日，数据可调）会想送主人点什么，从背包里的东西中按权重挑一样，拿在手上走过去递给主人。
- **送礼的池子**：背包里的东西，除了：
  - 主手的工具、身上的包；
  - 钱（`chiikawa:currency` 标签）；
  - 性格里标了"自己用"（`keep`）的东西，比如小八的相机；
  - 还没拍满的胶卷。
  拍满的胶卷权重高（暂定 5，其余 1），很快会被挑中。
- **池子空了**就不送；背包里能送的东西越多，越常有礼物，原来"钱多买得多、送得也多"的感觉还在。
- 坐下时不送；只有自己的宠物送；送的时候聊天框照旧告诉主人送了什么。

### 3.3 数据与代码

- **`data/chiikawa/pet_gifting/gifting.json`**（一份，整合包可以整个替换）：多久想送一次 `cooldown_ticks`（24000）、权重 `weights`（物品 id 或 `#` 标签加权重，没列的是 1）。
- **一件东西现在能不能送**由物品自己说（物品上的一个小接口），在 `keep` 之前问；胶卷只在拍满时说能送。这样以后别的东西也能定自己的规则，不用改送礼的代码。
- 商店里"给主人买"的逻辑和对应的聊天提示删掉；"待送礼物"格子保留，作为"拿在手上、正走过去"的那一份。送到一半被打断（主人走远、被叫坐下），东西放回背包。

## 4. 设置页面

### 4.1 来由

CurseForge 评论里反复出现三类需求：野生的太多、声音太吵、想让它们少说话。现在只能写数据包，对普通玩家太难。

### 4.2 内容

| 项 | 范围 | 默认 | 属于 | 说明 |
| --- | --- | --- | --- | --- |
| 野生生成倍率 | 0% 到 100% | 100% | 世界 | 0% 就是不再自然生成 |
| 说话频率 | 0% 到 200% | 100% | 世界 | 乘在每个说话时刻的几率上 |
| 显示对话气泡 | 开 / 关 | 开 | 客户端 | 只影响自己看不看得到 |
| 音量 | | | | 不做滑条：页面上写一句"音量在原版的'友好生物'里调"，因为宠物的声音本来就归那一类 |

- **和数据包的分工**：数据包给整合包作者做细调；设置只是几个倍率，乘在数据之上，不另存一份数值。
- **世界设置**存在世界里，跟着存档走；联机时只有管理员能改，改完同步给所有人，其他人看到的是只读。
- **客户端设置**存在 `config/chiikawa/client.json`。
- **入口**：只放在 Fabric 的 Mod Menu、NeoForge 和 Forge 模组列表里的"配置"按钮，不在手册里放。

### 4.3 代码

- **生成倍率**：生成权重在服务器启动时就写进了群系，那时还读不到世界里的设置。所以不改权重，而是在每次生成判定时按倍率掷一次（替换现在的 `checkAnimalSpawnRules`），设置改了立刻生效。也因此倍率只能往下调，想多生成要用数据包调权重。
- **说话频率**：乘在 `PetVoice#draw` 的几率上。
- **对话气泡**：`SpeechBubbleRenderer` 已经在隐藏界面时不画，在同一处加客户端设置的判断。嘴的动作照常。
- **页面**：用模组自己的界面组件（`client/ui/mc`），不引入别的配置库。Mod Menu 作为可选依赖，没装也不影响。

## 7. 实施步骤

每一步都在 1.21.1 上完成、测试通过、提交。

1. **参考书的配方**。
2. **设置页面**：世界设置的存储和同步、客户端设置、页面、三个入口；生成倍率、说话频率、对话气泡。
3. **相机模型和图标**：找参考、建模、确认；照片和胶卷的贴图。
4. **照片的底层**：照片库、网络、后台渲染拍照、看照片的界面。先用一个调试命令"从某只宠物的视角拍一张"验证画面，在原版、Sodium、Iris 和 Oculus 加常用光影包上都拍过，再接到小八身上。
5. **小八拍照**：`pet_camera` 数据、喜好的条件、商店、拍照意图、挑对象、送照片、台词。
