# 0.1.4 设计：行为不再打架，生活更像生活

> 0.1.3 的内容见 [v0.1.3-design.md](v0.1.3-design.md)。0.1.0 的 AI 分层见 [v0.1.0-ai-architecture.md](v0.1.0-ai-architecture.md)。原作资料见 [chiikawa-ip-research.md](chiikawa-ip-research.md)。

## 1. 目标与范围

| 内容 | 说明 |
| --- | --- |
| **行为不再打架** | 每件差事一个优先级数字：高的能打断低的，一样的互不打断，外部事件排队，每个状态只有一个主人。见第 3 节。 |
| **底层整理** | 所有行为统一成「差事」，走同一个生命周期；能做成数据的写成数据。玩家看不见，但以后加行为只「加」不「改」。见第 3、4 节。 |
| **职业** | 仍由主手决定，玩法不变；活儿的实现改成「通用动作 + 数据」；战斗态度单独成一个设置。见第 4 节。 |
| **主人的控制** | 指令、范围、主手和背包、工作牌、少量开关、口哨和铃铛。硬约束，宠物再活泼也不越界。见第 5 节。 |
| **行为池** | 闲着时按原因、按角色做生活小动作，取代现在的张望、溜达、发呆轮换。见第 6 节。 |
| **送礼** | 从「定时从背包抽一样」改成「有心意才送，挑自然的时机送」，不送工作物品。见第 7 节。 |
| **看得懂** | 头顶小图标、界面写清原因、决策日志。见第 8 节。 |
| **玩家反馈的零散问题** | 苦力怕躲小八、八音盒没歌不领演奏牌、Forge 更新检查误报、照片和 Distant Horizons / Oculus 的兼容。见第 9 节。 |

不做：盔甲（记下，原作角色基本不穿，要单独讨论怎么贴合）；职业由界面点选（会和主手形成两个来源）；背包里有什么就会什么活（调研后放弃，见 4.1）。

## 2. 现状与问题

### 2.1 规模

21 个意图（13 个通用、8 个随职业）、22 个活动、35 个行为、27 个自定义记忆、7 个感知器、10 类数据文件。数量不是问题，问题是下面这些。

### 2.2 打架和乱的根源

1. **谁能打断谁没有规则。** 选择器每 10 tick 重新打分，别的事分数高出容差就抢过去；分数相近的两件事来回抢。
2. **优先级靠分数相乘，和注释写的顺序不一致。** 吉伊早上收庄稼 0.6 × 1.32 = 0.79，压过考试 0.72；送礼 0.85 和战斗 0.8 在容差内，抛硬币；干劲加成加在倍率之前，早上的风狮爷 1.17 压过一切。0.1.3 说要做的硬优先级没有实现。
3. **一件差事的结束和失败后的休息散在四处，每个行为一套规矩。** 商店走不到或背包满了就无限重去；礼物 2 分钟没送出去，放回又立刻拿出；考试走不到时一直重试；拍照冷却由两个类四处写。
4. **同一件事有好几个来源。** 「闲着」「坐在考场」「在演奏」「拿着礼物」各有两三套判断且结论不同；动画状态被当成游戏逻辑用，音乐系统改动画就让行为停下。
5. **绕过选择器动宠物。** 口哨、考试成绩、传送、召回、任务奖励、照片送达都直接改宠物；别的宠物直接写它的记忆（小场面写伙伴的预约、血量、干劲；拍照摆姿势不管伙伴在干嘛）。
6. **每 10 tick 把 27 项情况全算一遍**，翻背包、查方块、抽随机数；调试指令看一眼也会改变它接下来做什么。
7. **职业各写一套。** 农夫有自己的感知器和 5 个位置记忆，先后顺序在感知器和意图里各写一遍；小判断复制三份；送礼不知道哪些是工作材料。

## 3. 新框架

### 3.1 四条铁律（由结构保证，不靠自觉）

1. **一个状态只有一个主人。** 「在做什么」「冷却多久」「往哪走」「手里拿什么」「播什么动画」各只有一个地方能写，别的代码拿不到写的入口。
2. **所有行为都是「差事」。** 干活、送礼、拍照、串门、闲时小动作，走同一个生命周期，没有特例和旁路。
3. **感知只陈述事实，决策只在一处。** 感知器写「附近有成熟庄稼」「在下雨」「主人回来了」，不替宠物做决定。
4. **外面的事不直接动宠物。** 口哨、成绩、传送、召回、别的宠物的邀请、照片送达，一律投进宠物的「收件箱」，由它下一次做决定时处理。

### 3.2 组成

```
   感知（只写事实）        收件箱（外部事件、邀请、结果回报）
          │                        │
          ▼                        ▼
 ┌────────────── 决策 ──────────────┐
 │ 1. 约束过滤：指令、范围、主手、主人开关   │  只能删候选，不打分
 │ 2. 优先级：只看最高优先级里能做的差事      │
 │ 3. 同优先级打分：性格、心情、环境          │  只能打分，不能删候选
 └──────────────┬──────────────────┘
                ▼
        执行器（唯一的「手」）
   拿着一件差事的计划，按步骤做：走、看、做动作、等、说话
   只有它能写走路目标、手持物品、动画、冷却
                ▼
   结果：完成 / 放弃 / 被打断 → 按数据记下歇多久
```

原版 Brain 保留，负责走路、看向、寻路这些执行细节；决策层和执行器是我们自己的。

### 3.3 差事的契约

每件差事只做两件事：

- **给出计划**：现在能不能做，能做的话目标是什么、要去哪里。**只读不写，不抽随机数**，调用两次结果一样。计划一旦开始，目标就定死，感知器不能偷换。
- **由公用步骤拼起来**：走过去、看着、做一个动作、等一会、说一句话、请伙伴配合。步骤是积木，差事只是排积木。

差事拿不到宠物的大脑，只拿到执行器发的「把手」，所以写不了别人的状态，也写不了冷却。

结果只有三种：**完成、放弃、被打断**。每种结果之后歇多久写在差事的数据里，由执行器统一记下。外部系统（照片送达、任务奖励）把结果报回收件箱，不再自己写冷却。

### 3.4 打断规则：只看优先级

不分固定的「层」。每件差事在自己的数据里写一个**优先级数字**，规则只有三条：

1. **优先级高的能打断优先级低的。**
2. **优先级一样的互不打断**，正在做的先做完；分数再高也只能排队。
3. **打断只发生在步骤之间。** 走路随时能停；一个动作（挥一下锄头、递出礼物、按一下快门）很短，做完这一下才停。所以收庄稼收到一半不会掉头走，最紧急的事也最多等一下。

挑新差事时：先找出现在能做的差事里最高的那个优先级，只在这个优先级里按性格、心情、环境打分挑一件。

一件事在不同情况下重要程度不同，就写成两件差事，各有自己的优先级。比如「跟随时护主」和「领了讨伐牌去打怪」是两件，前者高、后者和干活一样。

默认数值只是一个约定，方便读数据，不是代码里的分类，整合包可以改：

| 默认优先级 | 差事 |
| --- | --- |
| 100 | 受伤自保、口哨、主人改指令、传送和召回 |
| 80 | 跟随时护主、考试时间到、答应了伙伴的邀请、已拿在手上要送的礼物 |
| 50 | 干活、领牌子、演奏、拍照、讨伐牌 |
| 30 | 逛商店、串门、捡东西、送礼的心意 |
| 10 | 行为池的小动作 |

**不占身体的东西叠在任何差事上，但不算差事**：说话、东张西望、表情、头顶图标。各有自己的小规则（比如说话冷却），永远不让宠物停手或挪动。

### 3.5 状态归属

| 状态 | 唯一的主人 |
| --- | --- |
| 在做什么（差事和进行到哪一步） | 执行器 |
| 动画 | 由「在做什么」推导，不反过来当逻辑用 |
| 冷却和休息 | 执行器，按结果和数据写 |
| 走路目标、看向、手持物品 | 执行器（经由差事的把手） |
| 周围的事实（庄稼、商店、伙伴、天气、主人状态） | 感知器 |
| 外部事件、邀请、结果回报 | 收件箱 |
| 指令、家的位置、主人开关 | 主人的操作 |

宠物之间互动改成**邀请**：拍照的一方请伙伴摆姿势，串门的一方请伙伴配合。被邀请的一方由自己的决策按优先级决定接不接（接了就是「答应的邀请」这件差事，优先级见 3.4）；坐着的、正在打架的会拒绝。

### 3.6 用到才算

从高优先级往低查，每件差事轮到时才检查自己的条件，查到能做的那一级就停，不再把 27 项一次全算。调试指令只看不改。

## 4. 职业

### 4.1 主手决定职业，玩法不变

调研了东方女仆、Minecraft Comes Alive、Doggy Talents Next 等：受欢迎的做法是「主人明确选择干什么，工具只是前提」。主手正好同时是「选择」和「前提」，模型上看得见，一个来源。

- 界面点选职业：会和主手形成两个来源，东方女仆玩家一直抱怨打架时要开界面切换。
- 背包里有什么就会什么活：只有 Doggy Talents Next 作为可选天赋做过；东方女仆作者明确拒绝同时多任务，MCA 的自由差事是它 bug 最多的地方。

所以：**拿锄头的还是农夫，拿剑的还是剑士。**

### 4.2 活儿的实现：通用动作 + 数据

玩家看不见的整理。少量通用动作（采：打掉方块收获进背包；种：把背包里的东西放到或用到方块上；搬：存进或取出容器；打；演：演奏、拍照这类表演），每种配一套动画。

每种活儿一个数据文件，写清找什么目标、用哪个动作、需要什么工具和材料、产出放哪里、计入哪种工作牌、放弃后歇多久。收割、种植、送货、除草、采蘑菇、近战、远程、演奏都改写成这种数据。战斗走位、音乐流、照片渲染这些太特殊的逻辑仍写成代码，但以「动作」的身份接进同一个生命周期。

示意（格式在实现时定）：

```json
{
  "action": "harvest_block",
  "target": { "blocks": "#chiikawa:weeds" },
  "needs": "#chiikawa:farmer_tools",
  "tier": "work",
  "counter": "weed",
  "rest": { "gave_up": 600 }
}
```

每个职业在一处声明自己的工作物品（工具和材料），送礼、领牌子都读这一处。

### 4.3 背包

背包只放材料（种子、箭、胶卷）和存货。可选的**自卫换武器**：被攻击时自动从背包换上武器还手，打完换回工具。这是调研里玩家最想要、东方女仆一直缺的。由主人开关决定，默认开（第 11 节）。

### 4.4 战斗态度单独成一个设置

| 档位 | 行为 |
| --- | --- |
| 主动清怪 | 看到附近的敌对生物就上，和现在一样，默认 |
| 只帮你反击 | 像原版的狼，只打攻击你的和你正在打的 |
| 不参战 | 跟着你但不打，被打了就躲到你身后 |

和职业脱钩，参考 Recruits、Doggy Talents Next。跟随时护主优先级高，打起来不会被捡东西、送礼、拍照分心。血少撤退保留（35% 撤，60% 回）。自由活动时领了讨伐牌才主动去打，和干活同一优先级。没有武器的宠物被打时逃到你身边或家附近（受伤自保，优先级最高）。

## 5. 主人的控制

**主人定边界，宠物在边界里自己过日子。**

| 控制方式 | 管什么 |
| --- | --- |
| 指令：跟随、坐下、自由活动 | 在哪活动，现有，保持 |
| 主手和背包 | 干什么职业、有什么材料 |
| 工作牌 | 哪些活有报酬、优先做，现有，保持 |
| 战斗态度 | 见 4.4 |
| 少量开关 | 宠物界面里关掉某类事：逛商店、送礼、拍照、捡东西、串门 |
| 口哨糖、铃铛 | 当场让一群听话、叫回来，现有，保持 |
| 生活小动作频率 | 设置界面里和「说话频率」放在一起，存在世界里 |

这些都是硬约束：坐着就坐着，自由活动不出家的范围，你关掉的事它不做。唯一的例外是受伤自保，且只往你身边或家里逃（坐着时受伤也会站起来逃，安全了回原位接着坐）。

## 6. 行为池（最低优先级）

### 6.1 原则：要有趣，不要机械

1. **有原因**：看见、听见、感觉到了什么才做，不是骰子。
2. **同一件事，每个角色反应不同**：照原作里每个角色的样子，没有通用的一套。
3. **玩家看得懂**：配小图标、台词或动画。
4. **稀有和惊喜**：有些动作很少见、冷却很长；同一个动作不连着出现。
5. **小故事**：几个动作串成一段，比如发现花、摘下、拿去送人。

### 6.2 内容

| 类 | 例子 |
| --- | --- |
| 对环境 | 下雨躲树下或屋檐下（怕的缩到主人身边，不怕的在雨里玩）；天黑犯困回家附近睡；日出伸懒腰；雪地玩雪；闻花、偶尔摘一朵；盯着或追蝴蝶、蜜蜂、鸡；篝火边烤手；水边发呆 |
| 对主人 | 主人久别回来就迎上去；主人站着不动很久就过来坐旁边；主人挖矿盖房时在旁边看、加油；主人受伤跑过来担心；主人睡觉也在附近睡；主人吃东西时眼巴巴看着 |
| 对伙伴 | 打招呼、并排走一段、一起打盹、学对方的动作；现有五个小场面并入 |
| 角色专属 | 照原作，待你定（第 11 节） |

会影响进程的事不放进来（干活、买东西、正式送礼优先级更高）。行为池最多带一点小后果，比如摘的花能拿去送人。

### 6.3 数据

每个小动作一个数据文件：触发条件（天气、时间、附近的方块或生物标签、主人的状态）、哪些角色会做、权重和冷却、动画和台词。原有的「闲时小习惯」并进来。第一批做 10 个左右，通用和角色专属各半，每个都要动画，做精再加。

## 7. 送礼

### 7.1 参考

| 来源 | 借鉴 |
| --- | --- |
| 原版的猫 | 你睡醒时把礼物放在床边：时机自然，不打断任何事 |
| 动物森友会 | 有原因的回礼；有礼物时先说一声 |
| Minecraft Comes Alive | 头上提示，点一下领取 |
| 猫咪后院 | 你不在时把礼物留在家里 |
| 任天狗狗 | 散步时发现礼物 |

### 7.2 流程

1. **契机**：闲逛发现好东西、干活碰到稀有收获、领到工钱或考过证、你对它好（喂了好吃的、给了零花钱）、胶卷拍满。记下一份心意，一次只记一份。心意的优先级低于干活，**永远不打断干活**。
2. **挑自然的时机送出**，按顺序看：
   - 你在睡觉 → 天亮放在你床边（早安礼物）；
   - 你在它的范围里且它手上没活 → 拿出礼物走过来（这时变成「拿在手上要送的礼物」，优先级高于干活，见 3.4），头上冒图标，你也可以直接右键领；
   - 你长时间不在 → 0.1.4 不留在家里，心意过一阵就淡掉（留在家里等宠物窝一起做）。
3. **送什么**：见 7.3。
4. **多久一次**：见 7.4。
5. **怎么送**：做成小表演，按角色不同（待你定）。

背包不限制放什么，主人想放什么都行；管的是「拿出来送人的是什么」。

### 7.3 送什么

现状：背包存货格里不是钱、不是 keep 的东西都可能被抽中，胶卷权重 5、其余 1，所以农夫老送种子。改成三个来源，前面的有就送前面的：

| 来源 | 例子 |
| --- | --- |
| 为你准备的 | 拍满的胶卷；闲逛时摘的花、捡的小玩意；干活碰到的稀有收获。心意记下时就记住是哪一件，送出去的一定是它 |
| 它喜欢、愿意分你的 | 性格里喜欢的吃的，留一份自己吃，多的分你 |
| 角色专属 | 按原作，写在每个角色的数据里（待你定） |

永远不送：工作物品（4.2 的声明）、它想留着的（keep）、钱、数据里 `never` 列的。三个来源都没有东西时，这份心意就不送，不回退到随手抽，不送凑数的礼物。

### 7.4 多久一次

现状太勤：冷却 6000 tick（四分之一游戏日，现实 5 分钟），每只各算各的，冷却一到背包有东西就送。改为三道闸：

1. 要有契机才记下心意，每种契机有自己的几率。
2. 同一只宠物两次送礼最少隔一个游戏日（24000 tick）。
3. 一个主人一天最多收 3 份，所有宠物合计。

### 7.5 数据

`pet_gifting` 扩成能完整描述送什么、什么时候想送、多久一次（示意，格式实现时定）：

```json
{
  "min_interval_ticks": 24000,
  "owner_daily_limit": 3,
  "occasions": {
    "found_something": { "chance": 0.5 },
    "rare_harvest":    { "chance": 0.3 },
    "got_paid":        { "chance": 0.2 },
    "was_treated":     { "chance": 0.3, "delay_ticks": 1200 },
    "film_full":       { "chance": 1.0 }
  },
  "gifts": [
    { "items": "#chiikawa:gift_flowers", "weight": 3 },
    { "items": "#chiikawa:gift_snacks",  "weight": 2 },
    { "item": "minecraft:cookie", "weight": 4, "characters": ["chiikawa:chiikawa"] }
  ],
  "never": "#chiikawa:never_gifted"
}
```

用物品标签写，整合包加了新的花或点心只要往标签里添。0.1.3 的玩家现在就嫌多，可以先用数据包调大 `cooldown_ticks`，不另出小版本。

## 8. 看得懂

- **头顶小图标**：想送礼、累了、在找活干、被吓到、缺东西。
- **宠物界面**：现在做什么、接下来想做什么、为什么没在干活（「背包满了」「附近没有成熟的庄稼」「缺种子」）。缺东西时用角色自己的口吻说一句（参考 MCA「你有多余的锄头借我吗？」）。
- **决策日志**：每次换差事记下为什么选它、为什么没选别的；调试指令和界面看同一份。

## 10. 守住不再乱

1. **对所有差事统一跑的契约测试**，每加一件自动适用：在最长时限内结束；放弃和被打断一定记下休息；「给出计划」调用两次结果一样、没有副作用；被打断后不留残余状态（走路目标、预约、动画）。
2. **决策日志**：见第 8 节。
3. **注册表**：每件差事一个数据文件、最多一个类，列得清清楚楚，没有藏在角落里的行为。
4. **加新行为只加，不改**：新的小动作或新活儿是一个数据文件；全新的特殊玩法是一个新动作或新差事的类，挂进注册表，不碰决策和别的差事。
